# 校内赛 纳新仓库

组一辈子乐队 2025

比赛分为三个层级，由识别静态目标到识别多目标(不同类型)并打分排序，再到求解空间坐标并计算弹道 。

2. 订阅比赛阶段切换以作出相应调整

<h2 id="n71w3">流程</h2>
<h4 id="BYcUc">level1:</h4>

对图像进行预处理，调用各类模型对应的方法生成各类模型的列表，最后统一发送消息。此功能由张毅雄编写。

**圆形识别**  使用示例程序的，修改了预处理部分，因为装甲板灯条的颜色和球的颜色相近

**矩形识别**  先筛选出青色区域，再进行轮廓的查找，对轮廓进行筛选

矩形的筛选本来是通过逼近多边形，求边的个数判断，但是发现对于不在地面上的长方体，其形状为六边形，故为增强鲁棒性，识别条件改为轮廓所围的面积与求得最小矩形的面积比值相近

**装甲板识别**分为 _识别灯条_ _匹配灯条_ _识别数字_ 三部分

**灯条识别**

灯条为一个长条，我们求出其最小矩形，去除过于倾斜的，要求长宽比在一定范围内

**问题**： 当装甲板转过一定角度时，由于是模拟环境，灯条不发光，灯条的长宽比会变大，目前暂时将其上限提高，预处理部分用膨胀来改善这类情况下灯条的识别，视比赛情况是否会有此类情况再做调整

**匹配灯条**

我们将灯条按照 x 坐标进行排序，然后两两匹配

条件为长度比值 角度差值 以及是否有数字

因为条件里使用是否有数字进行了筛选所以较为可靠，对于已匹配的灯条进行标记不重复匹配

**数字识别**  数字识别分为 _提取数字_ 和 _识别数字_

**提取数字**

我们将灯条的矩形height延长一定倍数，由此匹配后装甲板会有4个新点

该组点包括了数字的部分，并且其透视改变与数字一致，故我们使用透视变换将其矫正

**数字识别**

使用模板匹配来识别数字

模板取自装甲板urdf目录

为提升性能，实际取1/4大小的模板，实测效果与正常尺寸差不多甚至略好

<h4 id="XGc8j">level2: </h4>
为level1写的程序本身已经支持多目标的检测，由于内容未给出，比赛期间会根据情况扩展各类型对应的结构体，在各目标检测方法中添加对应特征。此功能由董文彬编写。

由于比赛备赛阶段时同一类型的模型仅会出现一个，所以此时实际只需要根据前后两帧识别到的同一类型的中心点计算欧式距离即可实现跟踪。为此，这里实现了一个跟踪目标`TrackedObject`结构和目标跟踪`Trace`结构。考虑到比赛中可能会出现复数个相同外观的模型并进行跟踪，所以实现了`HungarianAlgorithm`类用来应对这一情况。

在`TrackedObject`结构中，使用卡尔曼滤波用来获取该目标下一帧抵达的预测点，随后在`Trace`结构中，定义了确定跟踪目标的属性（根据跟踪目标类型的不同分别进行物体跟踪）。在`Trace`结构中，直接用于跟踪的方法是`Trace::match_and_update()`，向这个方法传入当前目标的点的列表，即可进行前后帧的点的匹配，从而实现目标跟踪。

<h4 id="eHZVy">level3:</h4>
由于是备赛阶段，所以先将相应的逻辑写在原有的逻辑中，方便测试。此功能张毅雄编写。

**击打装甲板**  在level1识别装甲板的基础上，我们需要 _求解位置_ _预测位置_ _计算弹道_

**求解位置** 由于已知装甲板尺寸，使用PnP算法求解位置，opencv给出了求解pnp的函数使用即可

**预测位置**  卡尔曼还是太权威了，使用匀速模型

我们要预测弹丸飞行之后装甲板的位置，就需要知道预计的飞行时间，由于飞行时间差距应当不会太大所以我们粗略使用击打当前装甲板所需时间作为预测的时间(实际上可以使用迭代法来进行更精确的预测，但是这里必要不大有需要，比赛有时间再写)

我们能从`要求我们构造的服务`中获取的数据只有时间戳和物体用于pnp求解的原始尺寸矩阵

我决定取最新的一次识别结果进行计算返回发射角度(暂定)

**计算弹道**

实际上我们只需要求解发射仰角  忽略空气阻力(理想化)

弹丸的运动满足抛体运动，我们可以算出抛体运动的轨迹方程以及发射角度
